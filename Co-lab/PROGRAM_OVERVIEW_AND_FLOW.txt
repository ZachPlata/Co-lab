================================================================================
                       CO-LAB: STUDENT SKILL EXCHANGE
                   SYSTEM ARCHITECTURE & PROGRAM FLOW GUIDE
================================================================================

1. SYSTEM OVERVIEW
--------------------------------------------------------------------------------
Co-Lab is a peer-to-peer student skill exchange desktop platform built with 
C# (.NET 10.0 Windows Forms) and MySQL. It allows university students to 
register their academic/practical skillsets in their profile bio, publish skills 
to an open student marketplace, propose skill trades with fellow students, and 
track active and completed learning collaborations. A dedicated administrative 
portal provides listing moderation, category management, and policy updates.


2. ACTORS & USER ROLES
--------------------------------------------------------------------------------
A. Student:
   - Registers an account with school email and student details.
   - Adds known personal skills to their profile bio (knowledge repository).
   - Publishes selected bio skills into "My Listings" (public marketplace offers).
   - Searches and browses other students' listings in the "Skill Exchange".
   - Sends trade requests proposing reciprocal skill exchanges.
   - Accepts, rejects, or completes incoming trade requests.
   - Monitors incoming/sent trade statuses and dashboard metrics.

B. Administrator:
   - Monitors platform health, registered users, and active trade statistics.
   - Manages and adds official skill categories.
   - Moderates or bans inappropriate skill listings or reported students.
   - Updates platform Terms of Service (TOS) and regulations.


3. COMPLETE APPLICATION WORKFLOW
================================================================================

[STEP 1: LAUNCH & AUTHENTICATION]
--------------------------------------------------------------------------------
File: Program.cs -> LoginForm.cs
User Controls: UCAuth\uc_Login.cs, UCAuth\uc_Register.cs, UCAuth\uc_ForgotPassword.cs

1. Program.cs initializes the application and opens LoginForm.
2. LoginForm hosts a dynamic panel swapping between:
   - uc_Login: Student/Admin enters Email and Password.
     * System checks MySQL `users` table via AuthHelper.VerifyPassword().
     * If user.Role == 'admin' -> launches AdminMainForm.
     * If user.Role == 'student' -> initializes UserSession and launches StudentMainForm.
   - uc_Register: New student creates an account:
     * Full Name, Student ID, Email, Department/Degree, Password.
     * Must agree to Terms of Service (viewable via TosDialog).
     * Creates new record in `users` with Role = 'student'.
   - uc_ForgotPassword: Allows student to reset credentials.


[STEP 2: STUDENT ENTRY - DASHBOARD]
--------------------------------------------------------------------------------
Host: StudentMainForm.cs (Left Navigation: Dashboard, Skill Exchange, My Listings, Trade Requests)
Default View: UCStudents\uc_UserDashboard.cs

Upon logging in, the student arrives at their personal Dashboard:
1. Live Metrics Bar:
   - My Known Skills (Profile Bio count)
   - Pending Incoming Requests (requests from peers waiting for response)
   - Accepted Trades (currently ongoing collaborative learning sessions)
   - Outgoing Requests (sent proposals waiting for peer response)
2. Profile Bio Skills Repository (My Known Skills):
   - This represents what the student knows, NOT yet offered on the public market.
   - Student selects a Category and types a Skill Name, then clicks "Add to Bio".
   - The skill is stored in `student_skills` and automatically refreshes `dgvMySkills`.
   - Actions in table:
     * "Remove Skill": Removes skill from personal bio.
     * "Offer in My Listings ->": Seamlessly directs the student to "My Listings"
       with the chosen skill pre-selected so they can offer it publicly.
3. System Information:
   - "Read Terms & Guidelines" button launches the official TosDialog.


[STEP 3: PUBLISHING TO THE MARKETPLACE - "MY LISTINGS"]
--------------------------------------------------------------------------------
User Control: UCStudents\uc_ManageSkills.cs

To offer a skill to the university campus:
1. Post a Listing:
   - The dropdown "Select from your Known Skills" is dynamically populated 
     directly from the student's Bio Skills.
   - Student adds a listing description, learning goals, and trade preferences.
   - Clicks "Publish Listing".
   - Saved to MySQL `skill_listings` table (Status: 'active').
2. Manage Active Listings:
   - Displays all skills the student is currently offering.
   - Toggle Status: Temporarily pause a listing ('active' <-> 'inactive').
   - Delete Listing: Remove offer from the marketplace without deleting the 
     underlying skill from their profile bio.


[STEP 4: EXPLORATION & PROPOSAL - "SKILL EXCHANGE"]
--------------------------------------------------------------------------------
User Control: UCStudents\uc_SkillExchange.cs
Components: uc_SkillCard.cs, Propose skill exchange.cs

1. Marketplace Feed:
   - Displays listing cards (uc_SkillCard) published by OTHER students.
   - Excludes the logged-in student's own listings.
   - Real-time search bar (by skill title, keywords, or student name).
   - Category filter dropdown.
2. Proposing a Trade:
   - Student clicks "Request Trade" on any listing card.
   - Opens the "Propose Skill Exchange" dialog:
     * Displays target student's skill and description.
     * Requester selects which of their own offered skills to give in exchange.
     * Requester enters meeting location/mode (e.g., Campus Library, Gazebo, Discord)
       and an introductory learning note.
   - Clicking "Send Request" inserts a record into `trade_requests` 
     (Status: 'pending').


[STEP 5: TRADE MANAGEMENT - "TRADE REQUESTS"]
--------------------------------------------------------------------------------
User Control: UCStudents\uc_TradeRequests.cs
Tabs: uc_IncomingRequests.cs, uc_SentRequests.cs

1. Incoming Requests Tab (uc_IncomingRequests):
   - Shows proposals from peers requesting to learn from the logged-in student.
   - Actions:
     * "Accept": Sets status to 'accepted'. Both students can begin collaborating.
     * "Reject": Declines the trade proposal (status: 'rejected').
     * "Mark Completed": Once the peer-teaching sessions finish, sets status to 'completed'.
     * "Details": Views student details, notes, and session location.
2. Sent Requests Tab (uc_SentRequests):
   - Shows proposals the student sent to peers.
   - Status indicators: PENDING, ACCEPTED, REJECTED, COMPLETED.
   - Actions:
     * "Cancel Request": Withdraws proposal while still pending.
     * "Mark Completed": Confirms completed exchange once accepted.
     * "Details": Views peer info and trade parameters.


[STEP 6: ADMINISTRATIVE PORTAL]
--------------------------------------------------------------------------------
Host: AdminMainForm.cs
User Controls:
- UCAdmin\uc_AdminDashboard.cs: System-wide KPI cards, student registration trends,
  recent activity feed.
- UCAdmin\uc_ModerateListings.cs: Review flagged or suspicious listings; approve or remove.
- UCAdmin\uc_ReportedStudents.cs: Review reports against users and apply suspension/ban.
- UCAdmin\uc_SkillCategories.cs: Add, edit, or remove official system categories.
- UCAdmin\uc_UpdateTOS.cs: Edit live Terms of Service and academic integrity policies.


4. DATABASE ARCHITECTURE (MySQL: db_colab)
--------------------------------------------------------------------------------
- users:
    id, full_name, email, password_hash, role ('student'/'admin'), department, created_at
- skill_categories:
    id, name, description
- student_skills (Profile Bio):
    id, user_id, category_id, skill_name, created_at
- skill_listings (Marketplace):
    id, user_id, category_id, title, description, status ('active'/'inactive'), created_at
- trade_requests:
    id, requester_id, recipient_id, wanted_listing_id, offered_skill_id,
    preferred_location, notes, status ('pending'/'accepted'/'rejected'/'completed'),
    created_at, updated_at
- platform_settings / terms_of_service:
    content, last_updated
